## Opening a Folder Cold

You might have the practice folder from Foundations, the capstone checklist, or a project someone shared. Same steps either way. You do not need to have inherited a production app.

Navigate to the folder and start Claude:

```bash
cd ~/Documents/claude-code-practice
claude
```

## Orient Claude First

Do not jump straight into "fix this." Spend two minutes orienting Claude so every subsequent message is smarter:

```
> This folder is my practice project / daily checklist.
  I am getting set up.
  Can you map the folder — give me a high-level overview of the
  files and what each one seems to be for?
```

Claude will scan and produce a useful map:

- What the main files contain
- Patterns it recognizes
- Any obvious gaps

If you later open a larger app, the same prompt works — just add the stack you know ("This is a Next.js app using Supabase") when you know it.

## Getting Oriented Yourself

Ask follow-up questions to build a mental model:

```
> How does a task get saved in this project?
> Where would I change the heading on the page?
> What does @app.js do, in plain language?
```

These questions cost almost nothing.

<Callout type="tip">Use `@` references to load specific files into your orientation questions — for example, `@index.html` and `@app.js` together give Claude the picture, instead of making it guess from the folder list alone.</Callout>

## Finding Where to Make Changes

When you have a specific task, ask Claude to find the right place:

```
> I need to add a "created at" note to each task.
  Which files would I need to change?
```

## Creating a CLAUDE.md

Once you understand the folder, create a `CLAUDE.md` file in the root. This is loaded automatically every session. A tiny project still benefits:

```markdown
# Daily Checklist — Claude Code Context

## What This Is
A local page for today's tasks. No accounts. No server.

## Files
- index.html — the page
- styles.css — layout
- app.js — add, toggle, save

## Do Not Touch
- Anything that looks like a password or .env
```

With `CLAUDE.md` in place, every new session starts with Claude already knowing your conventions. Module 5 goes deeper. Remember: this file is context, not a security boundary.

<Callout type="info">On startup, Claude automatically reads your project structure, any `package.json` / `tsconfig.json` if they exist, git status, and any `CLAUDE.md` files. Conventions, decisions, and off-limits files are only known if you document them in `CLAUDE.md`.</Callout>

## Working on Unfamiliar Files

If a file has no comments and you did not write it, Claude Code is a documentation tool:

```
> @app.js — this file has no comments.
  Read through it and add short comments explaining what each
  function does, in plain language.
```

Do one function at a time. Read the diff.

## Summary

Opening a folder well sets up every future session. Invest a few minutes to orient Claude, create a short CLAUDE.md, and understand the files.

<KeyPoint>The minutes you spend orienting Claude and creating a CLAUDE.md when you first open a folder will save you from re-explaining context in every future session — it is the highest-leverage setup task you can do.</KeyPoint>
