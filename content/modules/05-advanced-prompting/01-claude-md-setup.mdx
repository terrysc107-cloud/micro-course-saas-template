## What Is CLAUDE.md?

You can write a CLAUDE.md for a tiny project. It does not require a team or a production app. A three-line file that says what the folder is for is already useful.

`CLAUDE.md` is a file you create in your project root that Claude Code reads automatically at the start of every session. It is your persistent project brief — once written, you never have to re-explain your stack, conventions, or constraints.

Without CLAUDE.md, every session starts cold. With it, Claude arrives already knowing your project.

It can live at `./CLAUDE.md` or `./.claude/CLAUDE.md` — both are loaded. Keep it in version control so anyone else who opens the folder gets the same context.

<Callout type="warning">CLAUDE.md is context, not a security boundary. Writing "never touch the payment code" shapes what Claude *tries* to do — it does not constrain what Claude Code is *allowed* to do. Permissions are enforced by Claude Code itself, not by the model. If something must not be modified, enforce it with a `/permissions` deny rule; a line in a markdown file is a request, not a lock. See the [permissions docs](https://code.claude.com/docs/en/permissions).</Callout>

## CLAUDE.md and Auto Memory

CLAUDE.md is not the only thing carrying knowledge between sessions. Claude Code also builds **auto memory** as it works — saving learnings like build commands and debugging insights across sessions without you writing anything.

The division of labor is worth understanding:

- **CLAUDE.md** — what *you* write. Standards, architecture, conventions, constraints. Deliberate and version-controlled.
- **Auto memory** — what *Claude* writes. Things it discovers while working, which it judges worth keeping.

They complement each other. Auto memory captures what you would never think to write down; CLAUDE.md captures what Claude would never infer. Both are loaded at the start of a session. See the [memory docs](https://code.claude.com/docs/en/memory) for current behavior — this area changes.

## Creating Your CLAUDE.md

To skip the blank page, start from [our CLAUDE.md template](/downloads/claude-md-template.md) and edit it down to your project. It is a starting point built for this course, not an official Anthropic artifact — delete anything that does not apply to you.

A filled-in example for the local checklist:

```markdown
# Daily Checklist — Claude Code Context

## What This Is
A local page for today's tasks. No accounts. No server.

## Files
- index.html — the page
- styles.css — layout
- app.js — add, toggle, save to localStorage

## Conventions
- A task is { id, title, done } with done true or false
- Empty titles are rejected before save

## Do Not Touch
- Anything that looks like a password or .env
```

If you later work in Next.js, the same file grows stack-specific sections. Start short.

<Callout type="tip">Run `/init` inside a Claude Code session to auto-generate a starter CLAUDE.md — Claude scans your project and creates a draft. Use this as the foundation and add the things only you know: conventions, off-limits areas, and work in progress.</Callout>

## Getting Claude to Write Your CLAUDE.md

Let Claude draft it:

```
> Based on scanning this folder, write a CLAUDE.md file
  that I will put in the root. Include: what this is, the files,
  patterns you see, and anything I should always follow.

  Ask me for anything you cannot infer.
```

Claude drafts it, you edit and add the things only you know.

## Subdirectory CLAUDE.md Files

For large projects, add CLAUDE.md in subdirectories. Subdirectory files are not loaded at launch — they load on demand. Skip this until you have a large project.

Claude Code also supports path-scoped rules in `.claude/rules/`. If your CLAUDE.md is growing past a couple of hundred lines, that is the mechanism to reach for.

<Callout type="info">CLAUDE.md is not a set-it-and-forget-it file — update it every time you establish a new pattern or agree on a new convention. A stale CLAUDE.md is worse than none because it actively gives Claude wrong assumptions.</Callout>

## Keeping It Updated

Review and update CLAUDE.md when you add a pattern, finish a major change, or start a new phase. It costs two minutes and saves ten minutes of re-explaining in every future session.

## Summary

CLAUDE.md is the highest-leverage file in your folder for long-term Claude Code work. Start from [our template](/downloads/claude-md-template.md), keep it short and specific, maintain it as you go. Just remember what it is: context that guides, not configuration that enforces.

<KeyPoint>CLAUDE.md turns every new session from a cold start into one where Claude already knows your folder, conventions, and constraints — but it is context, not a security boundary. It shapes intent; permissions enforce limits.</KeyPoint>
