## Automation = Leveraged Income

The highest-value service a developer can offer is automation. Here is why:

- You build it once
- The client pays for it every month (maintenance + hosting)
- You scale to 5-10 clients running the same types of automations
- Each client adds marginal revenue with minimal marginal work

Claude Code makes you fast enough that the first build is profitable even at a low rate. The maintenance retainers are pure margin.

## What Clients Need Automated

Walk into any small business and ask: "What do you do repeatedly that feels like busywork?" You will hear:

- "We export our sales data from Shopify every Monday and paste it into a spreadsheet"
- "We manually email customers 3 days after purchase to ask for a review"
- "We check our Google Analytics every week and write a summary for the team"
- "We sync our CRM contacts to our email platform manually"
- "We generate weekly reports from our database and email them to the CEO"

Every one of these is a script you can build with Claude Code in 2-4 hours.

## Example: Weekly Sales Report Automation

**Scoping session with Claude:**

```
> I want to build a weekly sales report automation for a client.
  They use Shopify for orders, have a Google Sheet for tracking, 
  and want an email report every Monday morning.
  
  Help me map out:
  - The data flow (Shopify API → process → email)
  - Edge cases (what if the API is down? What if there are no sales?)
  - What the report should contain
  - Deployment options (cron job, scheduled cloud function)
  - Rough time estimate to build
```

**Building it:**

```
> Create @automation/weekly-sales-report.ts
  
  Fetches last 7 days of Shopify orders via their REST API
  (SHOPIFY_STORE, SHOPIFY_ACCESS_TOKEN env vars)
  
  Calculates: total revenue, order count, average order value,
  top 3 products by revenue, new vs. returning customer split
  
  Sends HTML email via Resend API to REPORT_EMAIL_ADDRESS
  with a clean table layout
  
  Returns a summary object for logging
```

<Callout type="tip">Package each automation you build as a standalone, reusable script per client — give it its own repo, its own `.env.example`, and its own README. When a second client needs something similar, you have a starting point that takes 1 hour to adapt instead of 4 hours to rebuild.</Callout>

## Building a Reusable Automation Framework

After your first few automations, patterns repeat. Ask Claude to help you build a framework:

```
> I have built 5 client automations. They all share:
  - Fetching data from an external API
  - Transforming/aggregating the data
  - Sending an email report
  - Logging to a Google Sheet
  - Running on a weekly schedule
  
  Create @automations/framework/base-automation.ts with:
  - BaseAutomation class with run(), fetchData(), transform(), report() methods
  - Built-in retry logic for API failures
  - Structured logging to a log file
  - Error email alert if the automation fails
  
  Each new automation extends this base class and implements fetchData() and transform().
```

Now each new automation takes 1 hour instead of 4.

<Callout type="warning">Always test automations in a staging environment before delivering to a client — an automation that accidentally sends 500 duplicate emails, deletes the wrong records, or overwrites production data is a relationship-ending mistake. Add a `--dry-run` flag to every automation you build and run it in dry-run mode first, every single time.</Callout>
