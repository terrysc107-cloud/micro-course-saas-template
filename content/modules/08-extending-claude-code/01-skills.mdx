## The Problem Skills Solve

This module is later-course. If you do not yet have a checklist you keep pasting, skip it. Come back when a procedure has shown up three times.

You have a checklist. Before you ship a change you check that it is reversible, that you read the diff, and that there is an undo. You have pasted that checklist into Claude Code eleven times this month.

Or: a section of your `CLAUDE.md` started as three bullet points and has quietly grown into a nineteen-step procedure that is now loaded into every single session — including the ones where you are fixing a typo.

Both of those are skills waiting to happen.

A skill is a `SKILL.md` file containing instructions. Claude uses a skill when it is relevant, or you invoke one directly with `/skill-name`.

<KeyPoint>Create a skill when you keep pasting the same instructions, checklist, or multi-step procedure into chat — or when a section of CLAUDE.md has grown from a fact into a procedure.</KeyPoint>

## Where Skills Live

```
.claude/skills/<name>/SKILL.md     # project — commit it, the team gets it
~/.claude/skills/<name>/SKILL.md   # user — yours, across every project
```

Custom commands have been merged into skills. A file at `.claude/commands/deploy.md` and a skill at `.claude/skills/deploy/SKILL.md` both create `/deploy` and work the same way. If you already have a `.claude/commands/` directory, nothing breaks — those files keep working.

## The Naming Gotcha

**The command name comes from where the file lives, not from the frontmatter `name` field.**

| Skill location | Command name comes from | Result |
|---|---|---|
| `.claude/skills/deploy-staging/SKILL.md` | Directory name | `/deploy-staging` |
| `.claude/commands/deploy.md` | File name without extension | `/deploy` |

The frontmatter `name` field is the **display label** in skill listings. Setting `name: Staging Deployer` does not give you `/Staging Deployer`.

<Callout type="warning">If your skill is not showing up under the command you expected, check the directory name before you touch the frontmatter. Renaming `name:` will not move the command.</Callout>

## The Insight That Makes Skills Worth It

`CLAUDE.md` is loaded at the start of every session. Every line in it is a permanent tax on your context window.

A skill's body loads only when the skill is used.

So the rule of thumb:

- **`CLAUDE.md`** — short, always-true facts. "We use three files." "Empty titles are rejected."
- **Skill** — procedures, checklists, and long reference material that matter sometimes.

<Callout type="tip">Once a skill loads, its content stays in context for the rest of the conversation. Keep the body focused. "Free until needed" is not "free forever."</Callout>

## A Real Worked Example

Here is a review checklist as a skill. File: `.claude/skills/review-diff/SKILL.md`

```markdown
---
description: Reviews a diff before it is committed. Use when reviewing or accepting file changes.
when_to_use: review diff, git diff, before commit
allowed-tools: Read Grep Glob
---

Review the diff against every item below. Report each as PASS, FAIL, or N/A
with a one-line reason. Do not modify any files.

1. **Files** — does the file list match what was asked?
2. **Brief** — does any change contradict a written done-criterion?
3. **Scope** — is anything from the non-goals list present?
4. **Undo** — is there a commit to return to if this is wrong?

Finish with a single verdict line: `SAFE TO COMMIT` or `NEEDS WORK: <reason>`.
```

## The Frontmatter Fields Worth Knowing

**All fields are optional.** Only `description` is recommended.

| Field | What it does |
|---|---|
| `description` | What the skill does and when to use it |
| `when_to_use` | Extra trigger phrases |
| `allowed-tools` | Tools Claude can use without a permission prompt while the skill is active |
| `disable-model-invocation` | `true` means Claude will never load it on its own — only you, with `/name` |
| `context: fork` | Runs the skill in a forked subagent context |
| `paths` | Globs that limit when the skill auto-activates |

**`disable-model-invocation: true`** is for anything with consequences. A deploy skill should not fire because Claude decided the conversation sounded deploy-adjacent.

## When NOT to Write a Skill

- **You have done the task once.** Write a skill on the third repetition, not the first.
- **It is a fact, not a procedure.** "We use localStorage" belongs in `CLAUDE.md`.
- **The instruction is genuinely one-off.** Just type it.
- **You need a guarantee.** A skill is instructions to a model. If something *must* run after every edit, that is a hook — the next lesson. Skills persuade; hooks enforce.

## Get Started

Grab **[our Skill starter](/downloads/skill-template/SKILL.md)** — a commented `SKILL.md` template you can drop into `.claude/skills/<name>/` and fill in. It is a course asset, not an official Anthropic template.

Copy it, rename the directory, replace the body with your most-pasted checklist, and run `/your-skill-name`.

<Callout type="info">The official docs are the source of truth and Claude Code ships frequently — check [code.claude.com/docs/en/skills](https://code.claude.com/docs/en/skills) for the current frontmatter reference before you rely on a field.</Callout>

<KeyPoint>A skill is a `SKILL.md` file whose command name comes from its directory, not its frontmatter. Its body loads only when used — which makes long reference material affordable in a way CLAUDE.md never is.</KeyPoint>
