## The Loop Closes Here

Inspect, plan, build, review, test — and now ship. For this capstone, **ship** means: the page works on your computer, the brief's criteria pass in a browser, and you have a git commit you can return to. You do not need a hosting company.

That symmetry is the design: the document you wrote before you had any code decides whether the code is done.

## Browser QA

Your checks are green. That is not the same as working.

Open `index.html` in a browser. Open the brief. Go one by one:

**1. Add a task, refresh, it is still there.** Actually refresh. In-memory state looks perfect until reload.

**2. The list shows every task and whether it is done.** Add five. All five there?

**3. Mark done and not-done again.** Both directions.

**4. Open view shows only not-done tasks.** Mark two done. Do they vanish from Open? Do they return when you mark them not-done?

**5. Zero tasks and one task both render.** Delete everything. Look at it. Then one task.

**6. Empty title rejected with a message, not saved.** Submit blank. Message appears? Refresh — is a blank task there anyway?

<Callout type="warning">Criterion 6 is where "it looked like it failed" dies. The form says no, you see a message — and storage accepted it anyway. Refresh is the tell.</Callout>

### Then try to break it

- Submit twice fast. Two tasks?
- A title that's 500 characters. Layout survives?
- An apostrophe in a name. `O'Brien` is a real word and a real bug.

Write down each bug before you fix any of them. Fix-as-you-find means you stop QA at the first bug.

## Decide the Rollback First

Before you call it done. Not after.

**1. What exactly do I do to undo this?** `git log`, then `git checkout` or `git reset` to a named commit. Write the commit message of the known-good snapshot down.

**2. What does rollback NOT undo?** Saved tasks in localStorage. Reverting the files does not revert the browser store. If you changed field names, the old page may not read the new items. Know that before you need it.

**3. How will I know I need it?** Open the page. Add a task. Refresh. That's the check.

```
ROLLBACK PLAN

Undo: git checkout the commit titled "feat: open view".
Does NOT undo: localStorage. If I changed the task shape, I will
clear the store or keep a JSON export before I change shapes again.
Detection: add a task, refresh, confirm Open still works.
```

<Callout type="warning">"I'll just remember the good version" is not a rollback plan. A commit hash, or a commit message you can find, is.</Callout>

## Ship

Run [our ship checklist](/downloads/ship-checklist.md) as far as it applies. For a local project, the gate is: review, checks, browser QA, a known-good commit, a rollback that names what it does not undo.

Order that works:

1. **Walk the six criteria in the browser.** Yes, again.
2. **Record the known-good commit.** `git log -1` — copy the hash or the message somewhere you will find it.
3. **If you later put this on the internet**, preview first, and decide rollback before you publish. That is the optional Next.js path, not today's job.

<Callout type="tip">One commit hash, written down. It converts "undo" from an investigation into a command.</Callout>

## Roll Back Without Shame

If the checks fail: **roll back first, diagnose after.** A rollback is not a failure. It's the plan executing correctly.

## You've Run the Loop

Inspect, plan, build, review, test, ship — once, end to end, on something you can finish.

The checklist is disposable. What isn't: you wrote a brief before you had opinions about the files, argued with a plan while arguing was free, went slow at the data because that's where mistakes cost, built in increments small enough to actually review, reset instead of arguing with a poisoned context, wrote checks that would fail, got a reviewer who wasn't invested, and saved a version you can undo.

None of that is Claude Code-specific. The tool changes how fast the diff shows up. It doesn't change who is responsible for it.

When you are ready, you may run this same loop on the optional Next.js Lead Follow-Up build. Same six steps. Bigger stack. Not required.

## Before You Call It Done

- All six done-criteria checked in a browser, individually, against the written brief
- A few minutes of deliberate hostility, bugs written down and fixed
- Rollback plan written, including what it does not undo
- Known-good commit recorded

<KeyPoint>Every finish needs an undo decided before you need it — and it has to name what it does not undo, since reverting files does not revert saved data. Browser QA against the written brief, not against your memory of what you meant.</KeyPoint>
