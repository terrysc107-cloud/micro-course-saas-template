## Install It

The native installer is the recommended method in the current documentation. Pick the line for your platform and run it.

**macOS, Linux, WSL:**

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

**Windows PowerShell:**

```powershell
irm https://claude.ai/install.ps1 | iex
```

**Windows CMD:**

```batch
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

Your prompt tells you which Windows shell you are in: PowerShell shows `PS C:\`, CMD shows `C:\` with no `PS`. If you get `The token '&&' is not a valid statement separator`, you ran the CMD line in PowerShell. If you get `'irm' is not recognized`, you ran the PowerShell line in CMD.

Verify:

```bash
claude --version
```

<Callout type="info">If the install command fails with a `403`, a curl error, or `syntax error near unexpected token '<'`, the official [install troubleshooting page](https://code.claude.com/docs/en/troubleshoot-install) maps specific errors to specific fixes. Start there rather than guessing.</Callout>

## Alternatives, And What They Cost You

You do not have to use the native installer. You just have to know what you are giving up.

| Method | Command | Auto-updates? |
|---|---|---|
| Native | see above | Yes, in the background |
| Homebrew | `brew install --cask claude-code` | No |
| WinGet | `winget install Anthropic.ClaudeCode` | No |
| Linux package managers | apt, dnf, apk | Follows your package manager |

Linux package installs are available on Debian, Fedora, RHEL, and Alpine.

**This is the difference that matters.** Native installations update themselves in the background, so you stay on the latest version without thinking about it. Homebrew and WinGet installations do not. If you go that route, updating is a chore you now own:

```bash
brew upgrade claude-code
```

```powershell
winget upgrade Anthropic.ClaudeCode
```

Claude Code ships frequently. A month of skipped upgrades is a real gap in features and security fixes — and it is the most common reason a documented flag "doesn't exist" on someone's machine.

<Callout type="warning">Homebrew publishes two casks and they are not the same thing. `claude-code` tracks the stable channel — typically about a week behind, and it skips releases with major regressions. `claude-code@latest` tracks the latest channel and gets new versions as soon as they ship. Whichever you install is the one you must name when you upgrade.</Callout>

## Windows: One Extra Step

On **native Windows**, [Git for Windows](https://git-scm.com/downloads/win) is recommended so Claude Code can use the Bash tool. Without it, Claude Code uses PowerShell as its shell tool instead — workable, but a different execution surface than most documentation and most of this course assumes.

WSL setups do not need it.

## About That npm Command

If you learned Claude Code from an older tutorial, you probably saw this:

```bash
npm install -g @anthropic-ai/claude-code   # not the recommended path
```

Along with a claim that Node.js 18 or higher is required. Neither reflects the current documentation. The docs present the native install as the recommended method and state no Node version requirement for it. If you have an old npm-based install lying around, the native installer is where to go.

We are flagging this explicitly because it is still all over the internet, and because a course that quietly teaches the stale thing is worse than no course.

<Callout type="tip">Claude Code is not only a terminal tool. The same engine runs in VS Code, JetBrains IDEs, a desktop app, the web, and Slack — and your CLAUDE.md files, settings, and MCP servers carry across all of them. Install the CLI first; it is the surface everything else is described against.</Callout>

<KeyPoint>Use the native installer unless you have a specific reason not to — it is the recommended method and it is the only one that auto-updates. If you choose Homebrew or WinGet, upgrading is now your job, and a stale install is the single most common source of "that flag doesn't work for me."</KeyPoint>

Claude Code moves fast, and these commands come from the official [quickstart](https://code.claude.com/docs/en/quickstart) and [setup](https://code.claude.com/docs/en/setup) pages as verified for this course. If something here doesn't match what you see, the docs win — check them.
