## Two Ways In

Claude Code runs from your shell as either a conversation or a single shot. Knowing which you want before you type saves a surprising amount of time.

**Shell commands** — these start or resume Claude Code from your terminal:

| Command | What it does | Example |
|---|---|---|
| `claude` | Start interactive mode | `claude` |
| `claude "task"` | Run a one-time task | `claude "fix the build error"` |
| `claude -p "query"` | Run one-off query, then exit | `claude -p "explain this function"` |
| `claude -c` | Continue most recent conversation in current directory | `claude -c` |
| `claude -r` | Resume a previous conversation | `claude -r` |

`claude "task"` and `claude -p "query"` look similar and aren't. The first opens an interactive session with that as the opening prompt. The second answers and exits — no session, no back-and-forth.

## Sessions Persist

This trips up people coming from older tutorials, so let's be direct: **your conversations don't evaporate when you exit.**

```bash
claude -c          # continue the most recent conversation in this directory
claude -r          # resume a previous conversation
```

`-c` is the one you'll use daily. You close your laptop, come back after lunch, `claude -c`, and you're back in the same conversation with the same context. Inside a session, `/resume` does the same job.

<Callout type="tip">`claude -c` is directory-scoped — it continues the most recent conversation *in the current directory*. If you jump between repos, `-c` gives you the right thread per repo automatically. It's the closest thing Claude Code has to "just put me back where I was."</Callout>

## Session Commands

Once you're inside a session:

| Command | What it does |
|---|---|
| `/help` | Show available commands |
| `/clear` | Clear conversation history |
| `/exit` (or `Ctrl+D`) | Exit Claude Code |
| `/status` | Show the active account and auth method |
| `/config` | Open configuration |
| `/model` | See and change the current model |
| `/resume` | Continue a previous conversation |
| `/compact` | Summarize the conversation to free up context |
| `/permissions` | Manage permission rules |

Type `/` on its own to see everything you can invoke — built-in commands plus any skills available in this project.

## /compact vs /clear

These are not interchangeable, and picking wrong costs you real work.

- **`/compact`** summarizes the conversation and keeps going. Use it when you're deep in one task and running long — you need the earlier findings, just not every token of them.
- **`/clear`** wipes conversation history and starts fresh. Use it when you're *switching tasks*. Stale context from an unrelated problem doesn't just waste space; it actively pulls Claude toward irrelevant patterns.

The rule of thumb: **same task, `/compact`. Different task, `/clear`.**

<Callout type="info">Running `/clear` starts a new session, but the previous conversation is preserved and can be resumed with `/resume`. `/clear` isn't destructive to your history — it's destructive to your *current* context, which is the point.</Callout>

## Shortcuts Worth Memorizing

| Shortcut | What it does |
|---|---|
| `/` | List commands and skills |
| `@` | File path autocomplete |
| `Tab` | Complete |
| `↑` | Command history |
| `Shift+Tab` | Cycle permission modes |
| `Esc` | Interrupt Claude mid-turn |
| `Ctrl+D` | Exit |

`Shift+Tab` is the one that changes how you work rather than how fast you type — it's the whole subject of the next lesson.

`Esc` is the underrated one. When Claude is three tool calls into an approach you can already tell is wrong, interrupt it. The work done so far is kept, and you redirect from there instead of waiting politely for a bad answer to finish arriving.

## Piping and Scripting

`-p` is where Claude Code stops being a chat tool and starts being a Unix citizen:

```bash
tail -200 app.log | claude -p "Slack me if you see any anomalies"
```

```bash
git diff main --name-only | claude -p "review these changed files for security issues"
```

```bash
claude -p "translate new strings into French and raise a PR for review"
```

It reads stdin and writes stdout, so it composes with everything else in your shell. This is the door to CI jobs, git hooks, and the kind of small automation that's too specific to ever be a product.

<Callout type="warning">Think carefully before wiring `-p` into anything automated. A non-interactive run has no one to answer permission prompts — which means you need to have made deliberate decisions about what it's allowed to do, in advance. That's the next lesson, and it's not optional reading before you put this in a pipeline.</Callout>

## Models

`/model` shows and changes the model for the current session. That's the mechanism you want — not a model name memorized from a course.

We're not naming a default model anywhere in this material. Defaults change without notice, and a lesson that confidently names one is wrong within weeks. `/model` is always right; a name in a tutorial has a shelf life.

## Aliases

Small thing, adds up:

```bash
# ~/.zshrc
alias cc="claude"
alias ccp="claude -p"
alias ccc="claude -c"
```

<KeyPoint>Learn four things and you have the CLI: `claude` for a session, `-p` for one-shot and scripting, `-c` to pick up where you left off, and `/compact` vs `/clear` to manage context deliberately. Everything else you can find with `/help`.</KeyPoint>

Commands and shortcuts here come from the official [CLI reference](https://code.claude.com/docs/en/cli-reference), [commands reference](https://code.claude.com/docs/en/commands), and [interactive mode](https://code.claude.com/docs/en/interactive-mode) docs as verified for this course. Claude Code ships weekly and the command set grows — `/help` and the docs are the current truth.
