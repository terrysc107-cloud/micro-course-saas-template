## Claude Code Costs Are Manageable

Most developers spend $20-100/month on Claude Code. For the productivity gains, this is excellent ROI. But there are habits that keep you in the efficient range vs. habits that lead to surprise bills.

## Check Your Cost

Inside a session, type:

```
/cost
```

This shows how much the current session has cost. Do this periodically during long sessions.

Set a monthly spending cap in the Anthropic console to protect yourself from runaway usage.

<Callout type="tip">Use `/compact` aggressively — not just when you feel like the session is getting long, but on a schedule: after 20-30 minutes on any task. The summary Claude produces from a clean, active conversation is much more useful than one produced when Claude is already losing track of details.</Callout>

## The Biggest Cost Drivers

In order of token consumption:

1. **Long files loaded multiple times** — loading a 1000-line file repeatedly in a session
2. **Back-and-forth on unclear requirements** — 10 exchanges to clarify what you should have specified upfront
3. **Asking Claude to scan large codebases** — "read everything in src/"
4. **Not using /clear between tasks** — carrying irrelevant context through unrelated work

## Cost-Saving Habits

**Use /clear between tasks:**
```
> [finish task 1]
/clear
> [start task 2 fresh]
```

This is free. The context window resets. No stale context accumulating.

**Load files precisely:**

Instead of:
```
> Read the entire src/ directory
```

Do:
```
> Read @src/lib/auth.ts and @src/app/api/login/route.ts
```

Load exactly the files needed for the current task.

**Use /compact in long sessions:**

When a session has been going for 30+ minutes:
```
/compact
```

Claude summarizes the conversation to date, freeing up context while keeping important facts.

**Front-load your spec:**

A clear, detailed first prompt costs fewer tokens than 5 back-and-forth clarifications. Invest 2 minutes writing a complete spec upfront to save 20 minutes of dialogue.

**Use one-shot mode for questions:**

```bash
claude -p "What does this error mean: Cannot read properties of undefined"
```

One-shot mode (`-p`) is cheaper than opening a full interactive session for a quick question.

<Callout type="info">The `-p` one-shot mode is not just cheaper — it is often the right tool for quick questions because it does not carry state from previous work. A focused question gets a focused answer, without Claude trying to relate your question to whatever you were working on before.</Callout>

## Choosing the Right Model

Claude Code defaults to Claude 3.5 or 3.7 Sonnet — powerful but not the cheapest. You can switch mid-session:

```
/model claude-haiku-3
```

Haiku is faster and cheaper — excellent for:
- Simple utility functions
- Quick explanations
- Documentation generation

Use Sonnet or Opus for:
- Complex architecture decisions
- Security-sensitive code
- Multi-file features

## Monthly Budget Guidance

| Usage level | Typical cost/month |
|-------------|-------------------|
| Occasional (few sessions/week) | $5-15 |
| Regular (daily use) | $20-50 |
| Heavy (primary tool) | $50-150 |

These assume efficient usage habits. Careless usage can be 3-5x these numbers.

## Summary

Clear between tasks, load files precisely, spec well upfront, use /compact in long sessions, and monitor with /cost. These five habits keep Claude Code affordable while maximizing output.

<KeyPoint>The five habits that keep Claude Code costs under control: use `/clear` between unrelated tasks, load only the files you need, write a detailed spec upfront instead of clarifying over 10 messages, use `/compact` proactively, and use `-p` one-shot mode for quick questions — these alone can cut your usage costs in half.</KeyPoint>
