## Shipping with Confidence

Claude Code helps you ship faster. But fast shipping means nothing if you ship broken code. Use these review patterns in the hour before every deploy.

## The Pre-Ship Checklist Prompt

```
> I am about to deploy the notifications feature. Review these files:
  @src/lib/notifications.ts
  @src/app/api/notifications/route.ts
  @src/components/NotificationBell.tsx
  
  Pre-ship checklist:
  1. Every API route has auth check
  2. Every write operation validates input
  3. Every error is handled and returns an appropriate status code
  4. No console.log statements left in
  5. No hardcoded values that should be env vars
  6. No TODO comments that block shipping
  7. TypeScript compiles clean (no 'any' types masking errors)
  8. Loading and error states are handled in the UI
  
  Report any issues found.
```

<Callout type="tip">Have Claude do a final review pass immediately before you commit — not the same review you did while building, but a fresh one with the complete set of changes in view. This catches things like a `console.log` you added for debugging, a TODO you forgot to address, or a hardcoded value that should be an environment variable.</Callout>

## Loading & Error State Review

One of the most common polish items:

```
> Review @src/components/NotificationBell.tsx
  
  Check:
  - Is there a loading state while notifications are fetching?
  - Is there an error state if the fetch fails?
  - What does the user see if they have zero notifications?
  - What does the user see if the mark-as-read request fails?
  
  For any missing states, implement them.
```

## Accessibility Quick Pass

```
> Review @src/components/ for basic accessibility:
  - All interactive elements have aria labels
  - Images have alt text
  - Form inputs have associated labels
  - Keyboard navigation works (focus styles visible)
  - Color contrast issues on text over backgrounds
  
  Report issues and fix the most critical ones.
```

## Performance Polish

```
> Before I deploy, check @src/app/dashboard/page.tsx for:
  - Any data that could be cached (static or time-based)
  - Unnecessary re-renders (missing useMemo, useCallback)
  - Images that should be next/image instead of img
  - Any obviously slow database queries
```

## Clean Up Dead Code

```
> Scan @src for:
  - Unused imports
  - Commented-out code blocks
  - Variables declared but never used
  - Functions defined but never called
  
  List them with file and line number. Do not delete yet — just report.
```

Review the list and tell Claude which ones to actually delete.

<Callout type="success">Developers who use Claude for a pre-ship review consistently report shipping with more confidence — not because Claude is infallible, but because having a structured checklist enforced on every deploy means they stop waking up at 3am to fix things they knew they should have checked. The peace of mind is real.</Callout>

## Documentation Pass

```
> For each exported function in @src/lib/, add JSDoc comments that:
  - Describe what the function does (one sentence)
  - Document each parameter with @param
  - Document the return value with @returns
  - Add an @example if the usage is not obvious
  
  Only add documentation — do not change any logic.
```

## The 5-Minute End-to-End Test Script

Before deploy, ask Claude to write a manual test script:

```
> Write a manual QA checklist for the notifications feature.
  Step-by-step instructions someone could follow to verify 
  it works correctly end-to-end, including edge cases like:
  - Zero notifications
  - Many notifications (10+)
  - Marking all as read
  - The bell count updating after a new notification arrives
```

Run this yourself before pushing.

## Summary

Pre-ship review → loading/error states → accessibility → performance → dead code → docs → manual test. This hour of review prevents the kind of bugs that hurt users and wake you up at 3am.

<KeyPoint>The pre-ship checklist prompt — auth checks, input validation, error handling, no debug logs, no hardcoded values, TypeScript clean — takes five minutes and catches the issues that would otherwise take five hours to debug in production; make it a non-negotiable step before every deploy.</KeyPoint>
