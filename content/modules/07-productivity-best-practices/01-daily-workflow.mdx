## The Compounding Effect

These habits work on a small local project. "Session" here just means time you spend in Claude Code. You do not need a professional job for a morning brief.

Claude Code rewards habits. Used ad-hoc, it is a useful autocomplete. Used deliberately — with context loaded, scope held, and conventions written down — it becomes part of how you work. The difference is not the tool; it is whether you have built a practice around it.

## The Morning Context Load (2 minutes)

Start every session by orienting Claude:

```
> I am picking up where I left off yesterday.
  I am building the daily checklist / the notifications feature.
  Relevant files: @app.js or @src/lib/notifications.ts
  Today's goal: make mark-as-done work.
  What do we need to do first?
```

This 2-minute brief saves you 20 minutes of re-orienting yourself mentally.

<Callout type="tip">Start every session with a single sentence of context: "I am continuing work on the checklist — yesterday I finished save/load and today I am building the Open view." This anchors Claude immediately.</Callout>

## One Task Per Session

The most valuable habit: start a fresh session for each distinct task.

```bash
# Task 1: fix the empty-title reject
claude
> [work, accept fixes, /exit]

# Task 2: add the Open view
claude
> [work, /exit]
```

Each session is focused. Claude does not carry wrong assumptions from Task 1 into Task 2.

## The Rubber Duck Upgrade

Before asking Claude to write code, ask it to think first:

```
> I need to add an Open view that hides done tasks.
  Before writing any code, explain two approaches and recommend one
  for this folder.
```

Now you choose the approach with understanding.

## Timeboxed Sessions

Set a time limit. Without a limit, sessions drift and context accumulates.

- **Small fix**: 20 minutes
- **New piece**: 45-60 minutes

When the time is up, commit what is working and start fresh next session.

## The End-of-Day Commit Message

Before closing for the day:

```
> Here is my git diff --staged:
  [paste diff]

  Write a commit message for this work.
  Also: is there anything in this diff that looks unfinished?
```

You get a clean commit and a to-do reminder.

<Callout type="info">Batching similar tasks into one session is more efficient than spreading them across multiple sessions — if you have three similar changes, do them in one session while the context is warm.</Callout>

## Keeping CLAUDE.md Fresh

Every time you establish a new pattern:

```
> I just decided empty titles are always rejected before save.
  Update @CLAUDE.md to add this to the conventions section.
```

Takes 30 seconds. Saves minutes every future session.

## The Weekly Review

Once a week, spend 5 minutes asking:

```
> Review my recent work in git log and identify:
  - Any patterns that have been repeated
  - Any files that look inconsistent with our conventions
```

## Summary

Morning context load → one task per session → think first → timebox → end-of-day commit → update CLAUDE.md. Done consistently, this is what turns Claude Code from something you occasionally reach for into part of how you work.

<KeyPoint>The value of Claude Code compounds through consistent daily habits — a 2-minute morning context load, one task per session, thinking before asking for edits, and updating CLAUDE.md as you go. None of these is impressive on its own; the benefit comes from doing them every day rather than occasionally.</KeyPoint>
