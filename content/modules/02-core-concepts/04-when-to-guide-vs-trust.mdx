## The Spectrum of Trust

Not all coding tasks deserve the same level of oversight. Learning to calibrate this is what makes Claude Code feel effortless rather than risky.

## High Trust — Let Claude Run

These tasks are low risk and high routine. Give Claude the goal and let it go:

- **Boilerplate components** — form fields, modal dialogs, loading spinners
- **Utility functions** — formatters, validators, type helpers
- **CSS and styling** — layout tweaks, color changes, responsive adjustments
- **Documentation** — JSDoc, README sections, inline comments
- **Type annotations** — adding TypeScript types to existing JS code
- **Test scaffolding** — generating test file structure for a function you wrote

For these tasks, review the diff but do not overthink it. The blast radius of a bad utility function is small and easily fixed.

<Callout type="tip">For high-trust boilerplate tasks, you can give Claude even more freedom by saying "create all the files you need for this feature" — letting it scaffold the full structure without step-by-step prompting. Save the tight constraints for when the stakes are higher.</Callout>

## Medium Trust — Review Carefully

- **New API routes** — check the auth, input validation, and error handling
- **Database queries** — ensure parameterization, correct table names, proper indexes
- **Third-party integrations** — Stripe, Supabase, email providers — verify API calls match docs
- **Component logic with side effects** — useEffect hooks, event handlers with mutations

For these, read the diff line by line. Ask Claude to explain anything unclear.

## Low Trust — Tight Constraints

These tasks need your hand on the wheel:

- **Authentication and authorization** — security bugs here are catastrophic
- **Payment flows** — money is on the line, verify against Stripe/payment docs
- **Public-facing APIs** — breaking changes affect real users
- **Database migrations** — mistakes here can destroy data
- **Environment and secrets handling** — never let Claude touch actual credential values

For low-trust tasks, do not ask Claude to "just handle it." Instead, break it into tiny pieces and review each one independently.

## Spotting Scope Creep

Scope creep happens when Claude makes changes you did not ask for. It is almost always well-intentioned:

```
You: > Add a loading spinner to the Submit button

Claude: [adds spinner, also refactors the form to use react-hook-form, 
         changes the API call to use a new hook, updates three other components]
```

Reject the diff. Break it up:

```
You: > n — I only want the spinner. Do not change the form library 
      or the API call. Just wrap the button text in a conditional 
      that shows a spinner when isLoading is true.
```

Less is more. One focused change at a time.

## Breaking Big Tasks Down

If you catch yourself writing a prompt that starts with "Refactor the entire..." or "Rebuild the whole...", stop.

A task that touches more than 3-4 files at once is a candidate for breaking down:

1. "Update the data model in `@types/index.ts`"
2. "Update the API routes in `@src/api/` to use the new type"
3. "Update the components in `@src/components/` to match"
4. "Update the tests"

Each step is reviewable. Each step is reversible. The sum builds confidently toward the goal.

<Callout type="info">Signs you need tighter constraints: Claude is touching files you did not mention, the diff is more than 50 lines when you expected 5, or Claude is making architectural decisions instead of implementation ones. When you see these signals, press `n`, tighten your prompt, and try again.</Callout>

## Summary

- **Small, isolated changes**: trust Claude, review quickly
- **Core logic, auth, payments**: stay tightly in control
- **Big changes**: break them into small reviewable steps
- **Scope creep**: catch it, reject it, redirect

<KeyPoint>Match your level of oversight to the stakes: give Claude full freedom on boilerplate, review carefully on API routes and integrations, and keep tight control on auth, payments, and anything touching real data — this calibration is what separates confident Claude Code users from ones who create messes.</KeyPoint>

This calibration comes with practice. Start conservative — it is faster to loosen up once you trust the output patterns than to clean up a mess.
