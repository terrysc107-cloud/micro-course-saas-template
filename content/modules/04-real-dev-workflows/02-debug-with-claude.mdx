## Debugging Is a Dialogue

Claude Code is not a magic bug-fixing machine — it is a very smart collaborator. The quality of the diagnosis depends on the quality of the information you provide.

## The Perfect Bug Report

Give Claude everything it would need to reproduce the issue:

```
> I have a bug in the checkout flow.
  
  Expected: User completes Stripe payment, gets redirected to /dashboard
  Actual: User completes payment, Stripe webhook fires (I can see it in Stripe dashboard),
          but the user is redirected to /?upgrade=true as if they have no purchase.
  
  Relevant files:
  - @src/app/api/stripe/webhook/route.ts — handles the webhook
  - @src/proxy.ts — checks course_purchases table
  
  Error in server logs:
  "No purchase found for user undefined"
  
  The webhook event shows userId in metadata. What is wrong?
```

This gives Claude: the symptom, the expected behavior, the actual behavior, the relevant code, and the error message. It will find the bug.

<Callout type="tip">Always paste the full error message including the complete stack trace — not just the first line. The stack trace tells Claude exactly where in the call chain the error originated, which is often three levels above where the exception is thrown and far more useful than the error message itself.</Callout>

## Paste the Full Error

Always include the complete error, not just the first line:

```
> Getting this error when the page loads:
  
  Error: Cannot read properties of null (reading 'user_id')
      at getCompletedLessons (/src/lib/progress.ts:12:39)
      at DashboardPage (/src/app/dashboard/page.tsx:18:25)
  
  Relevant file: @src/lib/progress.ts
```

The stack trace tells Claude exactly where in the call chain it broke.

## Intermittent Bugs

For bugs that do not happen every time:

```
> This bug happens only when:
  - The user signs up (not on login)
  - AND their email has a + sign in it (like user+test@example.com)
  
  It does not happen with normal emails.
  
  The sign-up code is in @src/app/api/signup/route.ts
  What could be causing the special character issue?
```

Pattern recognition is Claude's strength — give it the pattern.

<Callout type="info">Tell Claude what you have already tried before asking for a solution — "I already checked X, Y, and Z" prevents Claude from suggesting the same things again and pushes it to look at less obvious causes. This alone can save three rounds of back-and-forth.</Callout>

## "It Was Working Before" Bugs

When a regression is introduced:

```
> This was working before my last commit. I added a new Supabase 
  query in @src/lib/progress.ts and now the dashboard is blank.
  
  The new code I added starts at line 34. Before that the 
  getCompletedLessons function only made one query. 
  Now it makes two and something is wrong with the second one.
```

Claude checks the interaction between the existing and new code.

## When You Are Just Stuck

Sometimes you do not have an error — the code just does not behave right:

```
> @src/components/CourseSidebar.tsx — the checkmarks are not 
  updating after I complete a quiz. I can see in the Network tab 
  that the /api/progress response includes the completed lesson.
  But the sidebar still shows the Circle icon instead of CheckCircle2.
  
  The completed prop is passed from the lesson page. 
  What is the flow and where could the state update be failing?
```

Claude traces the data flow and finds where the state disconnect is happening.

## Understanding the Fix

Never just accept a fix without understanding it:

```
You: [accepts fix]
You: > Why did adding router.refresh() after the API call fix the issue?
     What was happening before that caused the stale data?
```

Understanding why teaches you the pattern and prevents the same bug next time.

## When Claude Gets It Wrong

Sometimes the first diagnosis is off. Redirect with more information:

```
You: > I tried that fix but the bug still happens

Claude: [asks for more context]

You: > Actually, looking more carefully, the issue might be in the 
      data flow. The lesson page uses server components but the 
      sidebar is a client component. Could that cause a mismatch 
      in how the completed data is read?
```

Your debugging instincts plus Claude's pattern recognition is more powerful than either alone.

## Summary

Great debugging prompts include: the symptom, expected vs. actual, relevant files, the full error, and any patterns you have noticed. The rest is dialogue.

<KeyPoint>A great debugging prompt gives Claude the symptom, the expected vs. actual behavior, the relevant files, the full error with stack trace, and what you have already tried — the more context you provide upfront, the more likely Claude is to diagnose correctly on the first attempt.</KeyPoint>
