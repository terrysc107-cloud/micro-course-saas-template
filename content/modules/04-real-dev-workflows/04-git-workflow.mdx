## Claude Code as Your Git Assistant

Claude Code cannot push to GitHub, but it is excellent at helping you write clear commit messages, review your changes before committing, and generate PR descriptions.

## Writing Better Commit Messages

After making changes and staging them:

```bash
git add -p   # or git add specific files
```

Then ask Claude:

```
> I have these staged changes (run: git diff --staged):
  [paste the diff output]
  
  Write a conventional commit message that:
  - Uses format: type(scope): description
  - Describes WHY this change was made, not just what
  - Is under 72 characters for the subject line
  - Includes a brief body if there are multiple changes
```

<Callout type="tip">Use Claude to draft commit messages from the actual diff output — paste `git diff --staged` into your prompt and ask for a conventional commit message. This produces commit messages that are accurate and specific to what changed, rather than vague messages you type from memory.</Callout>

Conventional commit types: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `perf`

**Example output:**
```
feat(quiz): require quiz pass to unlock next lesson

Previously lessons unlocked sequentially regardless of quiz score.
Now the next lesson only unlocks after the current quiz is passed
with 70%+ score. Lesson progress is written atomically with quiz pass.
```

## Pre-Commit Code Review

Before committing anything important, ask Claude to review:

```
> Here is my git diff --staged output:
  [paste diff]
  
  Review this as if you are a senior developer doing a code review.
  Look for: bugs, missing error handling, security issues, 
  style inconsistencies, anything that should not be committed.
```

Claude catches issues before they hit your repo.

<Callout type="warning">Always review AI-written commit messages before pushing — Claude summarizes the diff accurately but cannot know the business context behind why you made the change. A message like "fix null check in user query" is less useful than "fix crash when guest user visits dashboard (users table has no row for guests)" — add that context yourself.</Callout>

## Branch Naming

```
> I am building a notifications feature that adds a bell icon 
  and a Supabase table for storing notifications.
  What should I name this branch? Give me 3 options following 
  conventional branch naming.
```

Output: `feat/notifications`, `feature/notification-bell`, `add-notifications`

## Generating PR Descriptions

After finishing a feature:

```
> Here is the output of git diff main...HEAD:
  [paste diff]
  
  Write a PR description with:
  - Summary (2-3 bullet points of what changed)
  - Why this change was made
  - Files changed and what each one does
  - How to test it manually
  - Any breaking changes or migration steps needed
```

This produces PR descriptions that your team will actually read.

## Resolving Merge Conflicts

When you hit a conflict:

```
> I have a merge conflict in @src/lib/progress.ts
  
  <<<< HEAD
  [your version]
  ====
  [incoming version]
  >>>> main
  
  Explain what both versions are trying to do and 
  write the correct merged version that keeps both changes.
```

Claude understands both sides of the conflict and writes the merged version correctly.

## Commit Grouping

When you have a lot of unstaged changes:

```
> Here is git diff on my working directory:
  [paste diff]
  
  These changes should be split into 2-3 logical commits.
  Suggest how to group them using git add -p and 
  what commit message to use for each group.
```

## Summary

Use Claude for commit messages, pre-commit reviews, PR descriptions, and merge conflict resolution. Your git history becomes clean and descriptive without the effort of writing it manually.

<KeyPoint>Claude is an excellent git assistant for drafting commit messages, reviewing diffs before committing, and writing PR descriptions — use it consistently and your git history will become a readable record of why changes were made, not just what changed.</KeyPoint>
