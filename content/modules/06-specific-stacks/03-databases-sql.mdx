## Claude Code + Databases

SQL is an area where Claude Code pays dividends. Schema design, query writing, index optimization, and migration planning are all tasks Claude handles very well — when you ask precisely.

## Schema Design

```
> Design a Postgres schema for a task management app.
  
  Requirements:
  - Users can create projects
  - Projects contain tasks
  - Tasks have: title, description, status (todo/in_progress/done), 
    priority (low/medium/high), assignee, due_date
  - Tasks can have subtasks
  - Support tagging tasks
  
  Output as SQL with:
  - Proper foreign key constraints
  - Created_at and updated_at timestamps on every table
  - RLS policies (using Supabase auth.uid())
  - Appropriate indexes for common query patterns
  - Enum types for status and priority
```

<Callout type="warning">Never run AI-generated SQL directly on your production database — always test it on a development or staging environment first. A migration that drops the wrong column or an UPDATE without a WHERE clause cannot be undone without a backup, regardless of how confidently the SQL was generated.</Callout>

## Writing Safe Queries

Always parameterized:

```
> In @src/lib/tasks.ts, write a getTasksByProject function
  
  It should:
  - Accept projectId and optional filters (status, assignee)
  - Use parameterized queries (never string interpolation)
  - Join with users table to get assignee name
  - Order by priority DESC, created_at ASC
  - Return typed TaskWithAssignee[] using @src/types/task.ts
```

<Callout type="tip">Before executing any non-trivial query Claude writes, ask it to explain what the query does in plain English — including what data it reads, what it modifies, and any edge cases. If the explanation reveals something unexpected, you have caught it before it runs against your data.</Callout>

## Summary

Always ask Claude to use parameterized queries, add RLS policies, and include appropriate indexes. These three habits keep your database secure and performant from day one.

<KeyPoint>Every table Claude creates should have RLS policies, every query should use parameterized inputs, and every migration should be tested on development before production — make these non-negotiable and you will never have a database security incident from AI-generated SQL.</KeyPoint>
