## Building APIs

Claude Code builds clean, consistent REST APIs when you specify the contract upfront.

## The Complete API Route Template

```
> Create @src/app/api/teams/[teamId]/members/route.ts
  
  GET /api/teams/:teamId/members
  - Auth required (return 401 if not authenticated)
  - Verify user is member of teamId (return 403 if not)
  - Return { members: TeamMember[] }
  
  POST /api/teams/:teamId/members  
  - Auth required
  - Verify user is team admin (return 403 if not admin)
  - Body: { email: string, role: 'member' | 'admin' }
  - Validate with zod (return 422 on invalid input)
  - Return 409 if user is already a member
  - Return { member: TeamMember } with 201 on success
  
  DELETE /api/teams/:teamId/members
  - Auth required, verify admin
  - Body: { userId: string }
  - Cannot remove yourself (return 400)
  - Return { success: true } on success
  
  Use types from @src/types/team.ts
  Follow patterns from @src/app/api/users/route.ts
```

## API Error Response Shape

Standardize error responses:

```
> All API routes in this project should return errors in this shape:
  { error: string, code?: string, details?: unknown }
  
  Update @src/app/api/teams/[teamId]/members/route.ts to use 
  this shape for all error responses. 
  Also create @src/lib/api-response.ts with helper functions:
  - success(data, status = 200)
  - error(message, status, code?, details?)
```

## API Client Library

```
> Create @src/lib/api-client.ts — a typed client for all internal API routes
  
  Include methods:
  - getTeamMembers(teamId): Promise<TeamMember[]>
  - addTeamMember(teamId, email, role): Promise<TeamMember>
  - removeTeamMember(teamId, userId): Promise<void>
  
  Each method should:
  - Handle HTTP errors and throw descriptive errors
  - Be fully typed using the types from @src/types/team.ts
```

<Callout type="tip">If the third-party API you are integrating has an OpenAPI spec (a `.yaml` or `.json` file), paste the relevant endpoint definitions directly into your prompt — this gives Claude exact request/response shapes, required headers, and error codes, producing integration code that is far more accurate than anything based on general knowledge alone.</Callout>

## Integrating a Third-Party API

When working with external APIs, paste the docs:

```
> I need to integrate the Resend email API.
  
  From their docs:
  POST https://api.resend.com/emails
  Authorization: Bearer {RESEND_API_KEY}
  Body: { from: string, to: string[], subject: string, html: string }
  
  Create @src/lib/email.ts with a sendEmail function that:
  - Accepts: to, subject, html
  - Uses the from address from RESEND_FROM_EMAIL env var
  - Handles API errors and throws with descriptive messages
  - Retries once on 429 (rate limit) after 1 second
  - Returns { id: string } on success
```

## Webhook Handler

```
> Create @src/app/api/webhooks/github/route.ts
  
  Handles GitHub webhook events for our deployment notifications.
  
  Security: Verify the X-Hub-Signature-256 header using 
  GITHUB_WEBHOOK_SECRET env var and the raw request body.
  Return 401 if signature is invalid.
  
  Handle event type 'push':
  - Parse the repository name and branch from the payload
  - If branch is 'main', trigger a deployment notification
    by calling @src/lib/notifications.ts createSystemNotification()
  
  Return 200 { received: true } for all valid events.
```

<Callout type="warning">In any API route that handles authentication tokens, always review how Claude manages the token lifecycle — check that tokens are never logged, never exposed in error responses, never sent to third-party services, and expire appropriately. AI-generated auth code that leaks tokens is the most common security issue in AI-built APIs.</Callout>

## Rate Limiting

```
> Add rate limiting to @src/app/api/auth/login/route.ts
  
  Limit: 5 requests per email per 15 minutes
  Storage: use a simple in-memory Map (sufficient for single-server; 
  note this does not persist across restarts)
  On rate limit exceeded: return 429 with Retry-After header
```

## Summary

API quality = auth + validation + error handling + consistent response shape. Give Claude the full contract — method, auth requirements, input shape, response shape, error cases — and it builds exactly what you specify.

<KeyPoint>Every API route Claude builds should have the same four elements by default: authentication check, input validation with zod, error handling with correct HTTP status codes, and a consistent response shape — specify all four in every prompt and your APIs will be production-ready from day one.</KeyPoint>
