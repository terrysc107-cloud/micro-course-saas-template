## CLI Tools Are Underrated

CLI tools are some of the highest-leverage things you can build. A well-built CLI that automates a 30-minute manual task pays for itself the first time someone uses it.

<Callout type="tip">Always specify the target OS and shell in your CLI tool prompt — "macOS/Linux bash," "cross-platform Node.js," or "Windows PowerShell compatible." Path separators, command syntax, and available utilities differ significantly, and Claude will default to one platform's conventions if you do not specify.</Callout>

## Building a Complete CLI

```
> Create @tools/generate-component.js — a CLI tool for our Next.js project
  
  Usage: node tools/generate-component.js ComponentName [--dir src/components/feature]
  
  What it does:
  1. Creates ComponentName.tsx with our standard React component template
  2. Creates ComponentName.test.tsx with the standard test scaffold
  3. Appends an export to the nearest index.ts barrel file
  
  Requirements:
  - Uses commander for argument parsing
  - Validates that ComponentName is PascalCase (error if not)
  - --dry-run flag shows what would be created without writing
  - --force flag overwrites if files already exist (default: error if exists)
  - Colored output with chalk (green = created, yellow = skipped, red = error)
  - Returns exit code 1 on any error
  
  Install commander and chalk first.
```

## Content Publishing CLI

```
> Create @cli/publish-lesson.ts
  
  Usage: ts-node cli/publish-lesson.ts <module-slug> <lesson-slug>
  
  What it does:
  1. Validates the MDX file exists in content/modules/
  2. Checks frontmatter is complete (all required fields present)
  3. Validates quiz has at least 3 questions and each has 4 options
  4. Runs a word count and warns if lesson is under 400 words
  5. Outputs a summary of what would be published
  
  This is read-only — no writes, just validation.
  Use gray-matter for frontmatter parsing.
```

## Data Migration Tool

```
> Create @scripts/migrate-users.ts
  
  Migrates user data from old_users table to new users schema.
  
  Flags:
  - --dry-run: show what would be migrated without writing
  - --limit N: only process N records (for testing)
  - --start-from ID: continue a paused migration from a specific user ID
  
  Behavior:
  - Reads in batches of 100
  - Prints progress: "Migrated 100/5000 users..."
  - Writes a migration log to migration-[timestamp].json
  - On error: logs the failed user ID and continues (does not abort)
  - Final summary: success count, error count, time elapsed
```

## Interactive CLI with Prompts

```
> Create @cli/setup.js using inquirer
  
  This runs the first-time setup for a developer joining the project:
  
  1. Ask for their name (text input)
  2. Ask which environment they are setting up (select: local/staging)
  3. Check if .env.local exists — if yes, ask to overwrite (confirm)
  4. Generate the .env.local file with the correct values for their choice
  5. Run npm install
  6. Print "Setup complete! Run npm run dev to start"
  
  No external config needed — env values are hardcoded for each environment.
```

## Shell Scripts

Claude Code writes shell scripts too:

```
> Create @scripts/deploy.sh
  
  Deployment script that:
  1. Runs TypeScript type check (fail if errors)
  2. Runs tests (fail if any fail)
  3. Runs next build (fail if build fails)
  4. Commits the build output to the deploy branch
  5. Pushes to origin (triggers Vercel deployment)
  
  Each step should print its status and stop on failure.
  Use set -e at the top so any error stops execution.
```

<Callout type="success">Once your CLI tool is working, Claude can write everything you need to distribute it via npm: a `bin` entry in `package.json`, a shebang line, README usage docs, and even a GitHub Actions workflow for publishing to npm. What started as a personal utility can be a public tool with half a day of extra work.</Callout>

## Summary

CLI tools built with Claude Code follow the Unix philosophy: do one thing well, have helpful output, support --dry-run for destructive operations, and return proper exit codes. Automate everything that gets done more than twice.

<KeyPoint>A well-built CLI tool that automates a 30-minute manual task pays for the time to build it on the very first use — specify the target OS, the argument interface, a `--dry-run` flag, proper exit codes, and colored output, and Claude will produce a tool that feels professional from day one.</KeyPoint>
