## Claude Code + Next.js App Router

Next.js App Router has strong conventions — Server Components, Client Components, Route Handlers, and layouts. Claude Code knows these patterns well when you guide it correctly.

## Server vs. Client Components

The most important concept to communicate to Claude:

```
> Create a ProductList component in @src/components/ProductList.tsx
  
  This should be a SERVER component (no 'use client' directive).
  It fetches products directly using the Supabase server client.
  It receives a categoryId prop and returns a list of products as JSX.
  No useState or useEffect — all async data fetching in the component body.
```

vs.

```
> Create an AddToCart button in @src/components/AddToCartButton.tsx
  
  This must be a CLIENT component ('use client' at top).
  It uses useState for the loading state and calls 
  POST /api/cart when clicked.
```

Claude will correctly use async/await at the top level for server components and hooks for client components.

<Callout type="tip">When prompting Claude for Next.js code, reference the official Next.js docs patterns by saying "follow the Next.js 14 App Router pattern for data fetching" or "use the recommended approach from the Next.js docs for this." This anchors Claude to current best practices rather than older Pages Router patterns that may be in its training data.</Callout>

## Route Handlers

```
> Create @src/app/api/products/route.ts
  
  GET handler:
  - Authenticate user with createClient() from @/lib/supabase/server
  - Return 401 if not authenticated
  - Query all active products from Supabase
  - Return { products } JSON
  
  POST handler:
  - Authenticate (same pattern)
  - Validate body with zod: { name: string, price: number, categoryId: string }
  - Insert new product to products table
  - Return { product } with 201 status
```

## Dynamic Routes

```
> Create @src/app/products/[productId]/page.tsx
  
  Server component that:
  - Receives params.productId
  - Fetches the product from Supabase
  - Returns notFound() if product does not exist
  - Renders the product details
  
  Also export generateMetadata that sets the page title to the product name
```

## Layouts with Data

```
> Update @src/app/(course)/layout.tsx to:
  - Be an async server component
  - Fetch the current user from Supabase
  - Redirect to /sign-in if no user
  - Pass user email to the header component
  - Render children inside a two-column layout (sidebar + main)
```

## Data Mutations with Server Actions

```
> Create a server action in @src/app/actions/cart.ts:
  
  export async function addToCart(productId: string) — 
    validates auth, inserts to cart table, revalidates the path
  
  'use server' directive at the top of the file
```

## useSWR / React Query Integration

```
> Create @src/hooks/useProducts.ts using SWR
  
  Fetches from /api/products
  Returns { products, loading, error, mutate }
  Types based on the Product type from @src/types/index.ts
```

<Callout type="info">Always tell Claude explicitly whether you are using the App Router or the Pages Router — they have different conventions for layouts, data fetching, and routing. If Claude is generating `getServerSideProps` when you expected `async` server components, this is why.</Callout>

## Common Next.js + Claude Code Patterns

**Loading states:**
```
> Add loading.tsx to @src/app/dashboard/ that shows 
  a skeleton of the dashboard layout while data loads
```

**Error handling:**
```
> Add error.tsx to @src/app/learn/ that shows a friendly 
  error message and a "Try Again" button that calls reset()
```

**Not found:**
```
> Add not-found.tsx to @src/app/learn/ for when a lesson 
  slug does not match any content file
```

## Summary

Always tell Claude whether each component is a Server Component or Client Component. Specify the data sources and mutation patterns. Next.js conventions are well-understood by Claude — just communicate the right constraints and it will produce idiomatic, production-ready App Router code.

<KeyPoint>The single most important thing to specify in every Next.js prompt is whether each component is a Server Component or Client Component — this one constraint determines everything about how Claude handles data fetching, state, and interactivity in the generated code.</KeyPoint>
